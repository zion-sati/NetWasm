# NetWasm 0.12.1: exit codes

NetWasm 0.12.1 is available on NuGet.org.

This patch ends a program with the exit code desktop .NET gives it, and adds
`Environment.Exit`, `Environment.ExitCode` and `Environment.FailFast`.

## Fixes

- A command whose `Main` returned a non-zero exit code reached the host as
  exit code 1, whatever the value, because `wasi:cli/run`'s result carries only
  success or failure. A non-zero exit code now ends the process through
  `wasi:cli/exit`'s `exit-with-code`, so Wasmtime, `dotnet run` and NetWasm's
  JavaScript hosts report it, truncated to the eight bits a process status has,
  as on Linux and macOS ([#214](https://github.com/zion-sati/NetWasm/issues/214)).

## New APIs

- `Environment.ExitCode` is the exit code of a `void` or `Task` `Main`; an
  `int` or `Task<int>` `Main`'s result takes its place, as on desktop .NET.
- `Environment.Exit(int)` ends the process at once with the code, after
  NetWasm ends the standard streams it opened.
- `Environment.FailFast(string?)` and `FailFast(string?, Exception?)` write
  .NET's "Process terminated." report to standard error, without the call
  stack, and end the process with exit status 134, as an abort ends .NET on
  Linux. No `catch` or `finally` runs.

A program's platform ends its process through the new
`NetWasmPlatform.ProcessExit` facade (`IProcessExit`). `WasiPlatform`
implements it over `wasi:cli/exit`; a plain core module's default platform
throws `PlatformNotSupportedException`, as for its other system services.

The `Console.WriteLine(42)` component is 37,506 bytes with the default Compact
collector, 481 more than with 0.12.0, for the `wasi:cli/exit` import every command
now carries.
