# NetWasm 0.10.8: CoreLib results that match .NET 11

NetWasm 0.10.8 is available on NuGet.org.

This release fixes the CoreLib differences reported in issues #149 to #152:
tasks, number formatting, generic math, string comparison, `Array.SetValue`
and the `GC` APIs now behave as they do in .NET 11. Most of the fixes replace
NetWasm's own implementations with .NET 11's. NetWasm's correctness tests now
compare every result with .NET 11 RC3. It also fixes the wrong results
reported in issues #159 and #160, each with tests that cover the whole kind of
mistake, not only the reported case.

Generated code is faster too. Across 2,202 of dotnet/performance's
micro-benchmarks, an `O3` application takes 0.95 of 0.10.7's time, and 0.425 of
Mono AOT's, where 0.10.7 took 0.448.

## Tasks

- `Task<T>.Result` on a faulted task throws an `AggregateException` that holds
  the task's exceptions, and on a canceled task one that holds a
  `TaskCanceledException`. It threw the task's exception itself. `await` and
  `GetAwaiter().GetResult()` still throw the first exception directly.
- `Task.WhenAll` no longer flattens an `AggregateException` that a task throws.
  It stays one of the exceptions of the task `WhenAll` returns.

## Exceptions

- An implicit exception, such as the `NullReferenceException` of a call on
  `null` or the `IndexOutOfRangeException` of an index past an array's end, is
  a new object on every throw, as in .NET (issue #160). Each kind was one
  shared object, so `Data` set on one throw showed on the next, and a
  collection could free what the shared object held. NetWasm now creates them
  as .NET's NativeAOT runtime does. Only `OutOfMemoryException` keeps a
  preallocated instance, for when allocating a new one fails.
- Stack traces leave out methods marked `[StackTraceHidden]`, and methods
  marked `AggressiveInlining`, as .NET does, so a throw helper's frame no
  longer heads the trace.

## Number formatting

- `double` and `float` format with `N`, `P` and `C`, which threw
  `FormatException`, and with every standard and custom numeric format .NET 11
  accepts. `decimal`'s `C` and `P` use the invariant culture's currency symbol
  (`¤`) and percent pattern instead of a hard-coded `$` and `%`, as .NET does
  under invariant globalization.
- Formatting with no format and no provider, which `ToString()`,
  `Console.WriteLine` and interpolation without a format use, still takes its
  own short path and does not reach the format-string code.
- `(-0.0m).ToString()` is `0.0`, as in .NET. It was `-0.0`.

## Generic math

- `ReadBigEndian`, `ReadLittleEndian` and their `TryRead` forms on the integer
  types accept shorter and longer spans as .NET does.
- `MaxMagnitude`, `MinMagnitude` and `CopySign` on the integer types no longer
  overflow at `MinValue`.
- On `float` and `double`, `MaxMagnitude`, `MinMagnitude`,
  `MaxMagnitudeNumber`, `MinMagnitudeNumber` and the `Math` overloads handle
  `+0`/`-0` ties and NaN as .NET does, and `MaxNumber` and `MinNumber` return
  the number when the other argument is NaN, including through generic code.
- `IsNormal`, `IsSubnormal`, `BitIncrement` and `BitDecrement` match .NET, and
  so do the `IFloatingPoint<T>` exponent and significand members such as
  `GetExponentShortestBitLength` and `TryWriteExponentBigEndian`, which
  returned fixed values.
- `CreateTruncating` from `float`, `double`, `Half` or `decimal` to `byte` and
  `sbyte` saturates as .NET does, and `decimal.CreateSaturating` handles NaN.
- `CompareTo` on the small integer types returns the difference, as .NET does.
- `float.Hypot` and `double.Hypot` are .NET 11's: `Hypot(Infinity, NaN)` is
  `Infinity`, as IEEE 754 requires, and `double.Hypot` no longer overflows
  past 1e154 or underflows below 1e-154. `RootN` is .NET 11's: `RootN(-8, 3)`
  is -2 where it was NaN, `RootN(x, 0)` is NaN, and zero and infinite results
  keep their sign.
- `float`'s members that .NET computes with `MathF`, such as `Sqrt`, `Cbrt`,
  `Log10`, `ScaleB` and `FusedMultiplyAdd`, call it, so `FusedMultiplyAdd`
  rounds once where it rounded through a `double`.
- `nint.BigMul` and `nuint.BigMul` return the product's high half on wasm32,
  where it was always zero, and no longer throw `OverflowException`. The
  `Parse` and `TryParse` overloads of `nint` and `nuint` use the `NumberStyles`
  and provider they are given, so hexadecimal parses.

## Unicode lookups

- `CharUnicodeInfo` is .NET 11's, and it gains `GetDecimalDigitValue` and
  `GetDigitValue`, which NetWasm lacked.
- Ordinal ignore-case search, comparison and hashing read the casing tables
  directly. On dotnet/performance's `ReadOnlySpan.IndexOfString`, the
  `OrdinalIgnoreCase` cases take 0.4 to 0.6 of their earlier time.

## Strings and arrays

- `string` is .NET 11's. Culture-sensitive comparison, search and casing give
  .NET's results under invariant globalization, which NetWasm always uses,
  where they threw `PlatformNotSupportedException`. `string.GetHashCode` is
  randomized per process, as in .NET, `new string(c, count)` past the maximum
  length throws `OverflowException`, the `char*` and `sbyte*` constructors
  compile, argument exceptions name their parameter, and string overloads that
  .NET does not have are gone.
- `Index` and `Range` are .NET 11's, and their exceptions name their
  parameter. `Span<T>`, `ReadOnlySpan<T>` and `string` no longer declare
  `Index` and `Range` indexers, which .NET does not have, so C# compiles
  `span[a..b]` and `text[^1]` to `Slice`, `Substring` and the `int` indexer, as
  it does for .NET.
- `char.IsAsciiHexDigitLower` and `char.IsAsciiHexDigitUpper` accept digits,
  and `char.IsBetween` over a reversed range matches the values outside it, as
  .NET's do.
- The indexed `string.Compare` and `string.CompareOrdinal` overloads clamp the
  length to each string's remaining characters and order `null` first. They
  threw when the length ran past the end of a string.
- `string.Split` is .NET 11's. A `null` string separator returns the whole
  string, as in .NET, where it split on white space, and a negative count
  throws `ArgumentOutOfRangeException`.
- `Array.SetValue` stores into arrays of value types, with .NET's widening of
  primitive values, such as an `int` into a `long[]`, and its exceptions. It
  threw for every value-type array.
- `ArraySegment<T>` is .NET 11's. A segment whose offset and count run past
  the array's end throws `ArgumentException`, where it threw
  `ArgumentOutOfRangeException`, and each exception names its parameter, as
  in .NET. `AsSpan` and `AsMemory` over a segment reject a start or length
  outside it, as they have since 0.10.7 (issue #152), and a test now compares
  each segment member with .NET 11.

## Garbage collection

- `GC.Collect` and `GC.CollectionCount` accept any non-negative generation.
  They threw for every generation but 0. Every NetWasm collection covers the
  whole heap.
- `GC.AddMemoryPressure` and `GC.RemoveMemoryPressure` work. Reported pressure
  runs a collection once it passes a budget, as Mono's collector does. They
  threw `PlatformNotSupportedException`.

## Compiler

- `Vector128.Asin` computes the arcsine, and so do `Vector256.Asin` and
  `Vector512.Asin`, which use it (issue #159). Every `Vector128` method whose
  name starts with `As` was compiled as a reinterpreting `As` method, such as
  `AsUInt64`, and returned its argument. The reinterpreting methods are now
  recognized by name, and the correctness tests compare 1,076 `Vector128`
  calls with .NET 11.
- `PackedSimd`'s ordered compares on `Vector128<ulong>`, such as
  `CompareGreaterThan` and `CompareLessThan`, compare unsigned. WebAssembly has
  no unsigned 64-bit lane compare, so they flip each lane's sign bit first.
  They compared signed. A test now checks every `PackedSimd` overload with
  signed or unsigned lanes against its element type's arithmetic.
- At `O2` and `O3`, `Math.Sqrt(y)` stays in a loop that writes `y` through a
  `ref`, span or pointer taken before the loop. It was moved out of the loop.
  No loop optimization now treats a local whose address the method takes as
  unchanged in a loop, including the folding of unrolled sums and the reuse of
  repeated calls.
- At `O1` to `O3`, `Math.Max` and `Math.Min` over an array keep a narrowing
  cast between two conversions, such as `(long)(sbyte)a[i]` over a `long[]`.
  The loop was folded as if the cast were not there.
- A `ref` local that holds an element of a span over constant data, such as
  `ref MemoryMarshal.GetReference(Table)` for a `ReadOnlySpan<byte>` property
  initialized with a collection expression, compiles when the local is
  assigned in a loop, after a jump or before an exception handler. At `O2`,
  `O3` and `Oz` it failed with NW1002, and at `O3` so did any application that
  decodes Base64, such as through `Convert.FromBase64String`. Tests now compile
  these shapes at every optimization level and compare their results, and the
  Base64 decoder's paths at `O3`, with .NET 11.
- A program without a JavaScript host, such as a WASI build of a library whose
  browser path checks `OperatingSystem.IsBrowser()`, compiles when it reaches
  `JSObject.Dispose` or `JSSubscription.Dispose`. The compiler stopped with an
  internal error. Without a host no object has a handle to release, so each
  call keeps only its null check.
- `Enum.Parse<TEnum>`, `Enum.TryParse<TEnum>` and `Enum.TryFormat<TEnum>`
  constrain `TEnum` only to a struct, so they accept a type that is not an
  enum, such as `int`. Such a program now compiles; it stopped the compiler
  with an internal error. These members, and `Enum`'s members that take a
  `Type`, throw `ArgumentException` "Type provided must be an Enum." for a
  type that is not an enum, naming `TEnum` or `enumType` as .NET does. They
  threw an `ArgumentException` with another message and no parameter name.
- At every preset but `O0`, a struct or tuple local stored into an array
  element, as `nodes[index] = parent` does in `PriorityQueue`'s sifts,
  compiles. Splitting the local into its fields deepened the evaluation stack
  past the depth the method declared, and the build failed with NW1002
  "evaluation stack exceeds maxstack".
- A class with `[StructLayout(LayoutKind.Explicit)]` places its fields at
  their `[FieldOffset]`, after its base's fields, so fields that overlap share
  their bytes, as a struct's always did. Its fields were laid out one after
  another, so a store to one overlapping field did not change the other. A
  layout that .NET refuses to load, such as a reference overlapping an
  integer or explicit layout over a base with automatic layout, fails the
  build with NW1003. At the optimizing presets, a field another field may
  overlap is also no longer read from an earlier read's value.
- `int.MinValue % -1` and `long.MinValue % -1` throw `OverflowException`, as
  .NET does. They returned 0.
- A program that calls `Type.GetGenericArguments` builds when a generic
  argument, such as the `char` in `Dictionary<char, Point>`, is not otherwise
  used. It failed with NW1008.
- A rebuild that takes methods from the compiler's cache emits the code a
  clean build does. The cache dropped what the compiler had proved about a
  method's array accesses, so a second build of an unchanged project could
  check accesses the first build left unchecked.
- A Release application built without `NetWasmStructuredDiagnostics` prints
  `NetWasm: unhandled exception. Build with NetWasmStructuredDiagnostics set to
  true to report its type, message and stack trace.` before it stops on an
  unhandled exception. Before, the host reported only a WebAssembly trap.

## Faster code

Each figure compares this release's `O3` build of a dotnet/performance
micro-benchmark with 0.10.7's, unless it names another workload.

- A remainder of the values a division just divided takes that division's
  quotient, `value - quotient * divisor`, instead of dividing again
  (issue #166, `NetWasmManagedQuotientReuse`). The division has already
  checked its operands, so the remainder needs no checks of its own.
- The compiler follows the ranges that integer locals and arguments can hold,
  through arithmetic, tests and loops, and leaves out the checks those ranges
  rule out (`NetWasmManagedIntegerCheckElimination`): the zero check of a
  divisor that cannot be zero, the `MinValue / -1` check of a signed division
  whose dividend cannot be `MinValue`, and the overflow check of checked
  arithmetic or a checked conversion whose result always fits. Both settings
  are on at every optimization level but `O0`. Issue #166's trial-division
  prime search below 10,000,000, run under Wasmtime, takes 765 ms with
  `value % divisor` where 0.10.7 took 1,376, and 760 ms when it divides once
  per step, where 0.10.7 took 1,128. Mono AOT takes 862 and 856 ms, and
  desktop .NET 11's JIT 1,156 and 685.
- A counted loop over a span runs without checking each index and four
  elements at a time, as loops over an array do: `SumIntsSpan` takes 0.56 of
  its 0.10.7 time.
- A loop that folds an expression of elements into an integer local, such as
  a dot product, runs as a `Vector128` loop. A walk by reference over n
  elements, `p = ref Unsafe.Add(ref p, 1)` with a count, runs four elements a
  group, and each element of an unrolled group, from a walk or an array loop,
  folds into an accumulator of its own: the strength-reduced loops of
  `Loops.StrengthReduction` take 2.2 us where they took 4.5.
- At `O3`, a `for` loop over a few constant values, such as a vector's lanes,
  runs its body once for each value in a row: `SeekUnroll` takes 0.78 of its
  time.
- Fills and copies of local arrays whose length is a constant skip their
  checks: Benchstone's `IniArray` takes 0.14 of its time.
- Loops over arrays of rank two or more read each array's shape once and
  index without strides: `MDInProd` and `MDMulMatrix` take 0.49 and 0.56 of
  their time.
- A one-dimensional array's elements are addressed at their fixed offset in
  the array, without first loading the array's data pointer
  (`NetWasmManagedInlineArrayData`, on at every optimization level but `O0`).
  SciMark's MonteCarlo takes 12% less time from this alone, and 0.67 of its
  0.10.7 time in all, now 5% less than under Mono AOT. Loops over jagged
  arrays, such as the `NeuralJagged` benchmark, take up to 17% less.
- A `static readonly` field whose static constructor stores a constant in it
  before anything else reads as that constant, so branches and arithmetic on
  it fold.
- A pure `Math` or `MathF` call made again on the same arguments reuses the
  first result: Benchstone's `BenchMk2` and `BenchMrk` take 0.66 and 0.63 of
  their time. A field read again before anything could change it reuses the
  first read, both arms of an `if` that store one field store it once where
  they meet, and an object is checked for null once before its repeated field
  accesses.
- Copies of values, `Unsafe.CopyBlock` and `Unsafe.InitBlock` of known sizes
  up to 128 bytes run inline at the speed presets.
- A type test against a class is one range check of the object's type id.
- Span arguments split into locals, and a vector's indexer reads the vector's
  value, so neither needs memory: `sum_static_array_via_local` takes 0.18 of
  its time.
- `MathF.Exp`, `Log` and `Log2` inline into their callers, and `MathF.Acosh`,
  `Cbrt` and `Log10` compute in single precision, as the C library Mono links
  does: `Single.Exp` takes 0.51 of its time and `Single.Cbrt` 0.33.
- `BigInteger` is .NET 11's, which keeps small values inline and multiplies
  large ones with Karatsuba and Toom-3: `PiDigits_3` takes 0.66 of its time.
- Small methods that upstream code reaches through long chains of
  `AggressiveInlining` calls are inlined, as .NET's JIT inlines them.
- Leaving a method with a value frame costs less, so a workload of decimal
  arithmetic and dictionary updates takes 8% less time.
- Slower: `double.Hypot` and `float.Hypot` take 5.3 and 2.7 times as long, as
  .NET 11's code, which handles the values the old one got wrong (see Generic
  math), and stay within 1.1 times Mono AOT's time. Linq's `GroupBy`,
  `CountBy` and `AggregateBy` over string keys take up to 1.26 times as long,
  as strings now hash with .NET's randomized hash, and still take about half
  of Mono AOT's time.

## SDK

- `dotnet publish` skips an application that sets `IsPublishable=false`, as
  .NET skips any project that does, whether the project is published alone
  or with its solution (issue #163). It failed with NWSDK003, because NetWasm's
  publish steps ran although .NET's publish did not. An application that
  publishes a referenced worker into its own output still publishes a worker
  that sets `IsPublishable=false`, and `dotnet run` still serves such a page.
- `dotnet publish --no-build` works when the project file is given by a path
  that goes through a symbolic link, such as macOS's `/tmp` and
  `/var/folders` (issue #162). When the build's artifacts really are stale,
  NWSDK003 now names the file or setting that changed.

## Tools

- `netwasm-wit-bindgen --help` (or `-h`) lists the options with an example,
  and running it without arguments shows the same usage. A command-line error
  points at `--help` (issue #158).
- `nwc` also accepts `-h` and `--help`, and follows a command-line error with a
  pointer to `-help`.
- A WIT error names the file as it was given, keeps the parser's lines with the
  caret under the column, and no longer carries Node's `ExperimentalWarning`.
  When a world imports a package that is not in its `deps` directory, the error
  says where the tools look for it.

## Testing

- Every pull request builds DoomSharp's render benchmark at each optimization
  preset with each collector, and requires each frame batch to have the pixel
  checksum desktop .NET renders.
- Each release also runs the compiler's corpus at `O3`. The library suites run
  at `O3` with NetWasmGC as well as unoptimized.
- Each optimization this release adds or changes has tests that break, one at
  a time, the conditions it relies on, and compare the results with .NET 11
  with the optimization on and off. Writing them found the explicit layout
  fixes above.
- A test compiles every public CoreLib member at every preset and validates
  the module. It found the `JSObject.Dispose`, `Enum` and array element store
  fixes above.

Rebuild an application to pick up the fixes. The one new setting is
`NetWasmManagedInlineArrayData`, which can turn the new array addressing off.
