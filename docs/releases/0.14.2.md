# NetWasm 0.14.2: Bump builds of programs that use ArrayPool

NetWasm 0.14.2 is available on NuGet.org.

This patch lets a program built with the Bump collector use `ArrayPool<T>.Shared`
again, along with finalizers, weak references and `ConditionalWeakTable`.

## Fixes

- In 0.14.0, a program built with `NetWasmGarbageCollector=Bump` failed to
  build with `NWPACK001` ("Bump collector does not support the 'finalization'
  runtime feature") as soon as it rented from `ArrayPool<T>.Shared`, directly
  or through a library that does. 0.14.0's shared pool trims itself after
  garbage collections, and it does that through an object with a finalizer and
  a weak reference, which Bump rejected. Bump now accepts finalizers, weak
  references and ephemerons, so these programs build and run again.

## What Bump does with finalizers and weak references

Bump never reclaims an object, so no object ever becomes unreachable to it.
Finalizers never run, weak references never clear, and a
`ConditionalWeakTable` keeps every value. This is what .NET promises: it runs a
finalizer only after a collection finds its object unreachable, and none when a
process exits. Programs and libraries that use these features therefore build
with Bump instead of being rejected, and behave as they would on .NET if no
collection ever ran. Compact and NetWasmGC are unchanged.

## Upgrading

Change `NetWasm.Sdk/0.14.1` to `NetWasm.Sdk/0.14.2` in your project. Nothing
else changes: 0.14.0's [release notes](https://github.com/zion-sati/NetWasm/blob/main/docs/releases/0.14.0.md)
describe the release these patches build on.
