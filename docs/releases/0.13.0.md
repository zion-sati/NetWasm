# NetWasm 0.13.0: programs carry no type names, calls through unmanaged function pointers, smaller programs

NetWasm 0.13.0 is available on NuGet.org.

This release breaks programs that print or compare type names: a program no
longer carries them, so a type reads `type#<id>` unless its names are loaded
from a file beside the program. In exchange, one `GetType().Name` no longer
grows every program by the names of all its types. It also adds calls through
unmanaged function pointers, makes async programs about half the size and the
program that prints 42 23% smaller, and fixes the console output that
JavaScript hosts could lose.

## Type names come from a file beside the program

- Breaking: `Type.Name`, `FullName` and `ToString()` read `type#<id>`, the
  type's runtime ID (`type#37`), and `Namespace` is `null`. So do the default
  `Object.ToString()` and `ValueType.ToString()`, the start of
  `Exception.ToString()`, and every framework message built from a type.
  Nothing throws for a name, and each type's text is unique, so maps keyed by
  type name keep working
  ([#225](https://github.com/zion-sati/NetWasm/issues/225)).
- Why: one reachable name read made every type with a runtime descriptor carry
  its name. The program that prints 42 grew from about 38.5 KB to 50.1 KB with
  one `GetType().Name`, and to 56.2 KB with one `GetType().FullName`. Names are
  now pay for use.
- `NetWasmTypeNames` (on in Debug, off in Release) writes every type's names to
  `<program>.wasm.type-symbols` beside the program; with it, names read exactly
  as .NET forms them, and an assembly name reads `<Assembly name unavailable>`.
  A component that exports synchronous WIT functions and has no process entry
  cannot read files when it starts, so its names read as IDs.
  Every build writes the exception types' names there, so a host's crash report
  names an unhandled exception's type even in Release.
- `NetWasmManagedStackTrace` (on in Debug) writes method names, and file and
  line in Debug, to `<program>.wasm.method-symbols`. Without it, a frame reads
  `method#<id>`.
- Breaking: every file beside the program, time zone data included, is opened
  under `/netwasm-sidecars/` by the name the build gave it (`App.wasm.tz-info`
  replaces `/netwasm-timezones/netwasm-timezones.nwtz`). Mounting the build or
  publish folder there just works:
  `wasmtime run --dir bin/Debug/netwasm0.1::/netwasm-sidecars App.wasm`.
  NetWasm's JavaScript hosts mount the same names.
- A missing, unreadable, malformed or stale symbols file never fails a program:
  it runs as if built without names, after one line to standard error.
- `ILogger<T>` categories keep their names (`Namespace.Type`): NetWasm's
  dependency injection generator writes them when it compiles the program.
- Member names (`MemberInfo.Name`, which expression trees and FluentValidation
  read) stay in the program: only members a program reads carry one.

## Calls through unmanaged function pointers

- `delegate* unmanaged<...>` calls native functions and `[UnmanagedCallersOnly]`
  methods with the C ABI's scalar, narrow, floating-point, pointer and
  aggregate signatures
  ([#226](https://github.com/zion-sati/NetWasm/issues/226)). A call through a
  managed function pointer with a value type result compiles too.
- Every calling convention .NET accepts on its 64-bit platforms means the C ABI,
  as it does there: `Cdecl`, `Stdcall` and `Thiscall`, with
  `SuppressGCTransition` or `MemberFunction`, on a function pointer, an
  `[UnmanagedCallersOnly]` method or a `[DllImport]` (its `CallingConvention`
  or `[UnmanagedCallConv]`). The `CallConv` types that name them are now in the
  framework, and an import marked `[SuppressGCTransition]` compiles. `Fastcall`,
  which .NET rejects everywhere, `Swift`, which it supports only on Apple
  platforms, and two base conventions at once fail with `NW1012` naming them.
- `sbyte`, `byte`, `short` and `ushort` cross as C's narrow integers in imports,
  callbacks and function pointers, as on .NET, where `NW1012` refused them.
- Several `DllImport`s of one native function, such as an `IntPtr` and a
  `byte*` overload, share its import, where the build failed with `NW1009`.
  Declarations whose C signatures differ fail with `NW1012` naming both.

## Smaller programs

- An async method's state machine publishes the references it holds to the
  collector precisely and once: a byref (a struct's `this`, as in `MoveNext`) is
  published, never everything it points into, an argument that never changes
  is not republished at every await, and what one path already published is not
  published again where paths join. Roots stay as precise as desktop .NET's.
- With that and type names leaving the program, an async workload of eight
  patterns (completed and suspending `Task`s and `ValueTask`s, chains,
  `Task.Yield`, `IValueTaskSource`, ping-pong, `IAsyncEnumerable`,
  `Task.WhenAll`) is about half the size in Release: 297,317 -> 151,466 bytes
  with the Compact collector at `Oz` (Brotli-11 46,957 -> 39,280), 301,318 ->
  155,444 with NetWasmGC, and 484,480 -> 305,650 with Compact at `O3`.
- The program that prints 42, the template's top-level
  `Console.WriteLine(42);`, is 29,244 bytes, 8,924 (23%) fewer than with
  0.12.2, from the same source: console output encodes UTF-8 without
  constructing an `Encoding` and writes integers without reaching culture
  state, a `Main` that never reads `args` no longer reads the command line, and
  a `void Main` that never sets `Environment.ExitCode` no longer imports
  `wasi:cli/exit`. Together they more than pay for its exit now closing the
  standard streams (#224, below).
- A `Main(string[] args)` that never reads `args`, as top-level statements that
  ignore them compile, no longer reads and copies the command line.
- A static field no code in the program writes reads as its default, so the
  code its value decides compiles away: a `void Main` whose program never sets
  `Environment.ExitCode` exits as an `int Main` returning 0 does. A program
  that sets the exit code exits with it, as on .NET.
  (`NetWasmManagedUnwrittenStaticFieldFolding`, on from `O2`.)

## Faster small copies and clears

- Span and array copies and clears of 17 to 64 bytes use Wasm's `memory.copy`
  and `memory.fill`, which Wasmtime runs faster than the unrolled loads and
  stores they replace: a 33-byte `Span<byte>.CopyTo` takes 14% less time and
  small `Span<T>.Clear` calls 4 to 13% less, with larger copies, fills and
  clears unchanged. Programs are smaller too.

## Diagnostics

- `NW1009` for a binding outside the selected WIT world now names the
  interface the program reaches and the line that adds it, for example
  ``imports 'wasi:cli/exit@0.3.2', which world 'wasi:clocks/imports@0.3.2' does
  not import; add `import wasi:cli/exit@0.3.2;` to the world``.
- `NW1013` (now `FunctionLimit`) also names a method that compiles to a function
  with more than 50,000 locals or 1,000 parameters, which browsers, Node and
  Wasmtime refuse, instead of failing after linking with a byte offset.

## Fixes

- A conditional branch to the next instruction, which a Debug build emits for
  an `if` around a call to a partial method without a body or a
  `[Conditional]` method, no longer crashes the compiler with NW1014
  ([#221](https://github.com/zion-sati/NetWasm/issues/221)). Every `leave` and
  try entry that ECMA-335 allows now compiles, including a `leave` that exits
  no block and a catch's `leave` back into its own try.
- A virtual or interface call over many boxed enums emits each shared target
  once, so `Convert.ChangeType(object, Type)` grows linearly with the number of
  enum types instead of with its square and no longer fails NW1013 at about 115
  enums ([#222](https://github.com/zion-sati/NetWasm/issues/222)).
- A delegate converts to another delegate type
  ([#223](https://github.com/zion-sati/NetWasm/issues/223)), and every method a
  delegate or function pointer can name binds and runs: an extension method's
  group, a struct's `base.Equals`, the groups of `ValueType.Equals` and
  `GetHashCode`, a boxed value's `GetType`, a `constrained.` method pointer and
  static virtuals, including a static abstract member called through a type
  parameter whose argument is a class that is not sealed
  ([#228](https://github.com/zion-sati/NetWasm/issues/228)). A delegate closed over a null instance throws
  `ArgumentException`, and `Enum.HasFlag(null)` throws `ArgumentNullException`,
  as on .NET.
- Console output in JavaScript hosts
  ([#224](https://github.com/zion-sati/NetWasm/issues/224)): a line written
  before a long computation appears at once and stays when a time limit stops
  the run, as on desktop .NET, because the host now takes the bytes when the
  program writes them instead of on a timer the computation starved. A
  program's exit closes each standard stream and waits for the host to write it
  out, and a program that yields resumes on the next turn of the event loop, so
  browsers print every line and 10,000 lines take under half a second on the
  Node.js host instead of about 12 seconds.
- A JavaScript host whose output sink refuses more output, as a page that caps
  its console does, no longer leaves the program waiting on its standard output
  until jco reports a deadlock: the program sees a closed pipe and runs on, as
  on .NET.
- A large program built with compiled units (the default at `O0` and `None`)
  no longer fails with `NW1014: Cannot allocate a buffer of size 2147483592`
  ([#229](https://github.com/zion-sati/NetWasm/issues/229)): a build writes as
  many cache segments as it needs, and stores each dispatch site's target list
  and each type test's matching types once rather than at every site, so the
  cache is smaller (by a fifth for the micro-benchmark runner at `O0`, and by
  more where many sites call widely implemented methods).
- A struct split into locals no longer stores its fields again before each call
  that takes its address when nothing changed them (`O1` to `O3`).
- Checking the neighbours of each fixed issue found two more. A function
  pointer to a `[JSImport]` method (`&Host.Twice`) calls the import through
  the forwarder a delegate uses, where it failed Wasm validation. And a
  struct's default `Equals` and `GetHashCode` keep the boxed value they compare
  alive when a field's own `Equals` or `GetHashCode` starts a collection, where
  they read freed memory: a wrong result on wasm32 and a trap on wasm64.

## Upgrading

- Code that prints or compares type names: compare `Type` objects, or build with
  `NetWasmTypeNames` and deploy `<program>.wasm.type-symbols` beside the program.
- Hosts that mounted time zone data at `/netwasm-timezones/`: mount the folder
  that holds `<program>.wasm.tz-info` at `/netwasm-sidecars/` instead.
