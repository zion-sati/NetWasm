# NetWasm 0.11.1: faster loops, arrays, frames and delegate calls

NetWasm 0.11.1 is available on NuGet.org.

This release makes compiled code faster. Kernel figures below are at `O3` with
NetWasmGC on an Apple M1 Max.

## Faster code

- A loop that computes a value, with branches, from values it never changes
  computes it once before the loop and reads the result. Expressions that can
  throw, read memory or call methods with effects stay in the loop, and so does
  an expression that only some iterations reach. The SeekUnroll kernel runs in
  332 ms instead of 724 ms. Every optimizing preset takes it;
  `NetWasmManagedLoopInvariantExpressionHoisting=Disabled` (`nwc
  -managedloopinvariantexpressionhoisting:Disabled`) turns it off.
- Within a block, an access to a rectangular array such as `int[,]` skips its
  null check after an earlier access to the same array, and each dimension
  check an earlier access to that array already made, while neither has been
  stored to. `MDAddArray2`'s inner loop ran eleven branches per iteration and
  now runs five: its kernel takes 8.6 ms instead of 14.0 ms (Mono AOT 10.3,
  desktop .NET 11 9.1).
- A type test whose pattern names the object, such as
  `value switch { Array array => ... }` on a type parameter, no longer boxes a
  value type: the test is resolved at compile time. Through the micro-benchmark
  runner's `Consume<Matrix4x4>`, which has such a switch, `CreateWorld` takes
  19.6 ns instead of 38.8 (Mono AOT 20.2) and `CreateLookAt` 33.4 instead of
  53.9 (Mono AOT 37.1).
- A block copy of one local into another of the same type, such as
  `Unsafe.CopyBlock(&destination, &source, (uint)sizeof(T))`, becomes a plain
  struct copy, as RyuJIT makes it, and the locals no longer live in frame
  memory for it. `StoreBlock.LocalAddress`'s `CopyBlock128` takes 10.9 ns
  instead of 14.0, `CopyBlock64` 7.0 instead of 8.4 and `CopyBlock32` 6.3
  instead of 7.8.
- A method whose body opens with an `if`, and whose value or root frame only
  one side of it needs, enters the frame on that side only. The other side,
  often the common one, runs without a frame. Across the 2,213 micro-benchmark
  cases this takes 2.4% less time (geometric mean), and 404 cases run more than
  5% faster. It is part of `NetWasmManagedBranchPrefixDuplication`.
- A single-cast delegate's invoke calls its target directly instead of going
  round the multicast loop. An empty static target through `Action` takes
  2.18 ns a call instead of 3.10, and a 100-entry multicast delegate 0.73 ns
  per entry instead of 1.41.

## CoreLib

- `System.Runtime.CompilerServices.Unsafe` is upstream's file at the .NET 11
  RC3 pin, unchanged, with NativeAOT's bodies for its intrinsics. 38 of its 45
  members were NetWasm's own stand-ins, and some signatures differed from
  upstream's, such as `As<T>(object? o)`'s parameter name and the missing
  `[AllowNull]` annotations.

## Fixes

- Two builds of the same program could produce different Wasm modules: the
  locals that replace a non-escaping object's fields were numbered in an order
  that varied from process to process. They now follow the fields' metadata
  order, and two builds by separate compiler processes are byte-identical
  ([#187](https://github.com/zion-sati/NetWasm/issues/187)).
- A module built with `NETWASM_KEEP_NAMES` for profiling kept no function
  names after the module merge, so a profile could not name its functions. The
  merged module now carries every input's function names
  ([#184](https://github.com/zion-sati/NetWasm/issues/184)).
