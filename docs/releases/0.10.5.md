# NetWasm 0.10.5: nwc, a native compiler

NetWasm 0.10.5 is available on NuGet.org.

This release ships the compiler as `nwc`, a native executable for each
supported development host, and fixes the in-browser compiler that the
Playground runs.

## nwc

- The compiler is `nwc`, built with .NET Native AOT for linux-x64, linux-arm64,
  osx-arm64, win-x64 and win-arm64. The `NetWasm.HostTools` package for the
  build machine carries it, so restoring a project restores the compiler with
  the other host tools.
- The SDK runs `nwc` as the C# build runs `csc`: the options go in a response
  file, and each line `nwc` writes appears in the build output. A compiler
  diagnostic such as `error NW1001: ...` is a build error with its code.
- The command line follows `csc`. `nwc -out:app.wasm -r:NetWasm.CoreLib.dll
  App.dll` compiles an executable from the assembly's entry point;
  `-target:library` compiles a library and `-target:function` a module that
  `-entry:Namespace.Type::Method` enters. Options also come from `@file`
  response files, and `-help` lists them all. This replaces the earlier
  `--input` and `--output` style options. See
  [CLI, build, and deployment](../cli-build-deployment.md).
- `nwc` prints its version banner first, unless `-nologo`, and reports every
  command-line error before it stops. A failure outside the compiler, such as a
  missing input file, is the new `NW1014` diagnostic.
- `NetWasmCompilerPath` names another `nwc` for a project, such as one built
  from source; an `nwc.dll` runs on the `dotnet` host.
- The host-tools package for macOS ARM64 is about 87 MB, up from 79 MB.

## Fixes

- The Playground's in-browser compiler, itself built with Native AOT, failed
  with "Reflection-based serialization has been disabled" when it generated
  raw bindings. The compiler and the SDK tooling now serialize JSON only
  through source-generated contracts, and every tooling project builds with
  the trimming and Native AOT analyzers, whose warnings fail the build.
