# NetWasm 0.10.6: variant interfaces through implicit implementations

NetWasm 0.10.6 is available on NuGet.org.

This release fixes generic variance through implicitly implemented interface
members. A class that implements `IEnumerable<string>` can be used as an
`IEnumerable<object>`, and enumerating it that way no longer throws
`InvalidCastException`.

## Fixes

- An implicit implementation whose return type is a variant instantiation of
  the slot's now fills that slot. A class whose public `GetEnumerator()`
  returns `IEnumerator<string>` is enumerated through `IEnumerable<object>`,
  and so is LINQ's `IGrouping<string, string>`. Before, the call had no
  target for that class and threw `InvalidCastException` at run time.
- The same holds for a contravariant parameter: an implicit
  `Accept(IEnumerable<object>)` implements `IAccepts<string>.Accept` when
  `IAccepts<in T>` takes an `IEnumerable<T>`.
- A method group whose return type is a variant interface instantiation binds
  to a delegate that returns the wider type, such as a method returning
  `IEnumerable<string>` assigned to a `Func<IEnumerable<object>>`.
- Explicit interface implementations and class-typed returns were not
  affected.

Rebuild an application to pick up the fix. There is no change to the SDK,
the runtime packages or the command line.
