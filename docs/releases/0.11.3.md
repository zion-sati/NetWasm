# NetWasm 0.11.3: native libraries can use Wasm SIMD

NetWasm 0.11.3 is available on NuGet.org.

This patch lets static native libraries use Wasm SIMD, as the code NetWasm
compiles already does, and names the library and the feature when an archive
uses one that NetWasm cannot link.

## Fixes

- A static native library (a `NativeLibrary` item) compiled with `-msimd128`
  failed to link with NWPACK001, and its validation log said "SIMD support is
  not enabled", although NetWasm's own compiled code has used Wasm SIMD since
  0.10.7. Native code may now use Wasm SIMD on wasm32 and wasm64, at every
  optimization level and with or without LTO
  ([#200](https://github.com/zion-sati/NetWasm/issues/200)).
- An archive that uses a WebAssembly feature outside NetWasm's static native
  profile, such as tail calls or threads, now fails with an error that names
  the library, the features the profile allows and the validator's reason,
  for example `Native library 'sum' uses WebAssembly beyond NetWasm's static
  native profile (...): tail calls support is not enabled`, instead of a
  message that a tool failed and a log path.

Programs without SIMD in their native code compile to the same bytes as with
0.11.2: the `Console.WriteLine(42)` component is byte-identical with every
collector.
