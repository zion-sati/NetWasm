# NetWasm 0.15.2: HTTP service handlers that finish

NetWasm 0.15.2 is available on NuGet.org.

This patch fixes the JavaScript host for HTTP services.

## Fixes

- Under the JavaScript host, an HTTP service component's handler never
  finished. Reading a request or response body tells the host, through a
  future, how the read ended; the host never read that future, so the
  program's write into it never completed and the handler stayed suspended
  after its response. A server that keeps the host running across requests,
  such as one on Deno or Node.js that instantiates the component for each
  request, kept scheduling every one of them: its idle CPU and memory grew
  with each request, and it no longer exited when asked to stop. The host now
  reads the future for request and response bodies alike: a service served by
  `deno serve` stays idle after 2,000 requests, its memory levels off, and it
  exits on `SIGTERM`.

## Upgrading

Change `NetWasm.Sdk/0.15.1` to `NetWasm.Sdk/0.15.2` in your project. Nothing
else changes: the [0.15.1 release notes](https://github.com/zion-sati/NetWasm/blob/main/docs/releases/0.15.1.md)
describe the release this patch builds on, and its known gaps still apply.
