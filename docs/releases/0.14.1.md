# NetWasm 0.14.1: O3 builds of methods inlining makes too large

NetWasm 0.14.1 is available on NuGet.org.

This patch lets a method build at `O3` when inlining into it would make its
WebAssembly function larger than browsers and Node accept, instead of failing
the build with `NW1013`.

## Fixes

- At `O3`, inlining could make one method's WebAssembly function larger than
  the 7,654,321 bytes, or the 50,000 locals, that browsers and Node accept,
  and the build failed with `NW1013` although the method built at every other
  level. TUnit on NetWasm's test engine was one: its test executor came to
  7.9 MB at `O3`. The compiler now compiles such a method again with nothing
  inlined into it, and the build succeeds. A method that is over the limit even
  then still fails with `NW1013`, as before. A program whose functions all fit
  compiles once, to the same bytes as 0.14.0.
- An incremental build that patched edited methods into the last build's
  module did not check their functions against those limits, so an edited
  method could make a module that engines refuse to load. It now checks them,
  and recompiles an edited method with less inlining in the same way.

## Upgrading

Change `NetWasm.Sdk/0.14.0` to `NetWasm.Sdk/0.14.1` in your project. Nothing
else changes: 0.14.0's [release notes](https://github.com/zion-sati/NetWasm/blob/main/docs/releases/0.14.0.md)
describe the release this patch builds on.
